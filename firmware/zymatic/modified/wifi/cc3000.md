# Zymatic CC3000 socket transport

This component exercises the local HTTP server over the Zymatic's Wi-Fi socket protocol on the bench. The USB installer uses this listener in both profiles at the Home menu and read-only recipe pauses. The extended profile also serves its About pairing screen. Heating, circulation and draining retain the original radio client. [Foreground scheduling](integration/README.md)

The socket transport opens a TCP listener on the supplied port, enables nonblocking accept and handles one client. It uses the radio's 5 ms socket-readiness check before requesting up to 16 bytes. A read completes in two parts, a command completion followed by its data packet. A write reports the number of bytes acknowledged by the radio. The physical SPI transfer and the caller accepting some bytes into a queue occur earlier. The listener and the OEM outbound client share a single radio command engine. [TI host driver socket operations](https://github.com/adafruit/Adafruit_CC3000_Library/blob/3327fd02c33703a5d5fe50672336e5a484ca513b/utility/socket.cpp) · [Adafruit TCP listener](https://github.com/adafruit/Adafruit_CC3000_Library/blob/3327fd02c33703a5d5fe50672336e5a484ca513b/Adafruit_CC3000_Server.cpp)

## Firmware evidence

The instruction test uses the verified 1.1.14 application. For each captured request it runs the corresponding retained OEM socket builder to the SPI boundary and compares the frame bytes. Where the outbound wrapper is absent, the native test checks the command against the TI protocol. The test executes the original event decoder for every socket operation used here, including bind, listen, accept and setsockopt. The replies supplied to this test are synthetic. [Instruction test](tests/cc3000_oem.cjs) · [Command vectors](tests/cc3000_native.c)

| 1.1.14 byte address | Function confirmed in the OEM application |
|---|---|
| `0x14984`, `0x146ec`, `0x14692`, `0x14d54`, `0x148ec` | Socket, select, receive, send and close request builders |
| `0x1550e` | Publishes the RX packet pointer and invokes the unsolicited-event classifier at `0x15522` |
| `0x13e20`, `0x13e0e` | Wait for the current command completion or the following data packet |
| `0x136ee` | Decodes the current response into the synchronous caller's result buffer |
| `0x12d3e` | Submits a command or data frame to SPI |

The IRQ test verifies that a regular accept completion remains pending, including when another opcode is expected. The original asynchronous classifier consumes returned TX credits and failed-send notifications. Credit availability is at SRAM `0x2659`, packets submitted and released are at `0x2661` and `0x2665`, and the active-socket mask begins at `0x09be`. The bench writer charges one shared credit when the radio signals readiness for a data write. If SPI fails partway, it leaves the charge in place and closes the radio transport for the remainder of the boot. [TI flow-control and event handling](https://github.com/adafruit/Adafruit_CC3000_Library/blob/3327fd02c33703a5d5fe50672336e5a484ca513b/utility/evnt_handler.cpp)

## Board integration

The broker reserves the complete HCI transaction for one caller, including the data packet following a successful receive. Original callers retain their own response buffers, socket notifications and TX credits. A waiting original caller has priority at the next command boundary. A timeout invalidates the lease until the radio reinitializes because a late socket response has no transaction identifier. [Radio broker](cc3000_broker.c) · [Arbitration tests](tests/cc3000_broker_native.c)

The stock write routine asserts the CC3000 chip select, changes the AVR SPI registers and waits for the radio IRQ. Its compiled failure branches at `0x12ed2` and `0x12ed4` loop indefinitely. The bench SPI transport binds only after stock radio initialization. Its IRQ handler records a pending edge. The foreground submits or receives a complete normal-state SPI frame and restores chip select and the previous SPI mode before returning. A pending inbound frame takes priority over a write. Reception borrows the stock buffer at `0x253a`, accepts up to 125 HCI bytes and excludes the stock guard at `0x25b7`. Further transfers wait for the consumer to release the frame. [AVR SPI transport](cc3000_spi.c) · [Original SPI instruction comparisons](tests/cc3000_spi.cjs)

The bench allowance for one transaction is 192 ticks of the stock Timer 0 counter (768 μs). A shared poll limit bounds CPU work if the timer stalls. These are software limits pending measurements on a real board. A lost IRQ, a stalled byte or an oversized frame leaves CS deasserted, masks the radio IRQ and closes the transport for the rest of this boot. Timer interrupts remain enabled during SPI waits. No reset or change to PD7 is assumed. The instruction test compares three complete outgoing and three incoming transfers against the original driver, including the original clocked padding. It also exercises lost interrupts, partial writes, exhausted credits and pending display work. [TI host-driver SPI framing](https://github.com/adafruit/Adafruit_CC3000_Library/blob/3327fd02c33703a5d5fe50672336e5a484ca513b/ccspi.cpp)

Selecting Wi-Fi at boot leaves the release's W5100 listener dormant. The Timer 3 supervisor still accesses SPI to draw the OLED. Its call at `0x10f60` reaches the display through two renderers. Both set SPI mode 0 before flushing the same framebuffer. The bench handoff substitutes the display epilogues at `0x5044` and `0x8738`. It lets the stock code update the framebuffer and finish the supervisor work during a radio transaction, then flushes the latest frame when the bus becomes available. The test compares the 4,102 SPI bytes with the final original frame and checks that both renderers retained the radio's SPI mode while waiting. These flushes use SPI data-out and never read data-in. While stock owns the radio, an asserted stock chip select also defers the display. The display flush masks only the radio IRQ and restores it when finished. The foreground radio receiver samples the IRQ level again after the display yields. [AVR display handoff](cc3000_spi_bus.c) · [Original and patched instruction comparison](tests/cc3000_display.cjs)

The AVR board adapter binds the listener after the original WLAN callback has recorded association and DHCP. Each foreground service call polls the radio, routes the received packet and services the same HTTP context used by the firmware. A returned credit, DHCP notification or disconnect executes the real 1.1.14 decoder. The instruction test sends HTTP over modeled SPI registers, reads the compact website, receives a 401 response when the device key is missing and receives the enrolled UID with a valid key. [Board adapter](cc3000_board.c) · [SPI-to-HTTP test](tests/cc3000_board.cjs)

An ordinary access-point disconnect drops the HTTP request, lets an outstanding receive finish, and explicitly closes its client and listener descriptors. A new listener opens after association and a successful DHCP event. The adapter forwards the original application callback, including when the stock menu holds the radio, and remembers a disconnect even if the station reconnects before the menu returns. A deliberate stock radio restart requires a fresh OEM callback installation and a ready driver before the next bind. The AVR tests exercise these cases and distinguish them from a missing command response, which keeps the radio quarantined. [Board and reconnection tests](tests/cc3000_board.cjs)

### Sharing Wi-Fi with the physical menus

The bench can lend the whole radio to stock code at a command boundary. An instruction test runs the original synchronous TCP socket routine using the OEM IRQ dispatcher, transmits the original request over simulated SPI, receives socket 3, runs stock detach, and resumes the HTTP-side writer. A second test exercises the original SyncUser menu's TCP failure path and checks that it restores the controller supervisor. Another test requests an OEM loan during a simulated browser's pending select, waits for its response, then executes the original SyncUser menu and its socket, connect, send, select, receive and close routines over simulated CC3000 pins. The modeled Hub replies with a two-step recipe. The test checks the transmitted URL, stock brew-bank name, ID and step count, restores the HTTP lease and finishes serving the open client. [SPI ownership tests](tests/cc3000_spi.cjs)

The OEM foreground has 11 direct calls to the radio attach routine at `0x129ae` and 12 exits through `0x12922`. The host driver also installs those same addresses as internal callbacks. A scheduler must take the lease before a foreground action suspends the supervisor or changes the menu, and must resume that action if a pending HTTP operation owns the radio. For example, the recipe-list path resets the list before calling SyncUser. Its Wi-Fi branch clears the Timer 3 supervisor gate at `0x9000`, then treats an unsuccessful connection as a network error. The OEM completion loop at `0x136ee` has a 3,001 ms timeout enabled only in specific diagnostic states and otherwise continues polling for its outstanding opcode. Returning “busy” from deep inside that loop would strand the caller. The instruction test verifies the direct and indirect sites and both completion-loop behaviors. [OEM call and completion tests](tests/cc3000_oem.cjs)

The OEM constructor assigns logical pins 20, 2 and 15 to chip select, IRQ and the WLAN-enable callback. The instruction test executes the stock GPIO routines. Startup drives PD7 low as an output, waits 500 ms, configures PC4 as an output and configures PB2 as an input with its pull-up enabled. The shutdown routine at `0x15388` drives pin 15 low, waits for IRQ to go high, then releases driver buffers and disables its interrupt. Startup at `0x153c2` also waits for IRQ edges before issuing commands. The stock Ethernet path configures PD6 and PD7 as outputs. Its register read and write paths both drive PD7 high and then low. [Instruction test](tests/cc3000_oem.cjs) · [TI WLAN initialization and shutdown](https://software-dl.ti.com/ecs/simplelink/cc3000/public/doxygen_API/v1.12/html/group__wlan__api.html)

The physical connection between PD7 and the CC3000 module's `VBAT_SW_EN` remains unverified for the Zymatic board. The first hardware evidence needed is the control-board and module revisions, a matching schematic or traced connections, and passive signals during ordinary OEM Wi-Fi and Ethernet activity. Compare PD7 with the module enable, any intervening gate or select signal, the peripheral chip selects, the radio IRQ and the shared clock and data lines. A firmware dump alone cannot distinguish a direct connection from an intervening latch or multiplexer. The CC3000 data sheet specifies the module's data output state during reset and its SPI timing during normal operation. The delay to release the Zymatic's shared bus after an interrupted transfer still needs measurement. [TI CC3000 module datasheet, tables 1 and 4](https://cdn.sparkfun.com/datasheets/Wireless/WiFi/cc3000.pdf)

Adafruit documented a CC3000 breakout whose data-out remained driven after chip deselect. Its shield included a separate buffer for use with other peripherals. This illustrates why the Zymatic board revision matters when returning to Ethernet after a radio fault. For a Wi-Fi-only boot, an active data-out line alone does not change the bytes seen by the write-only OLED. Its chip select and SPI mode still need the handoff above. [Adafruit CC3000 pinouts](https://learn.adafruit.com/adafruit-cc3000-wifi?view=all#connections)

Subsequent qualification on a test board requires confirming that the next peripheral transaction succeeds after a radio timeout, that the brewer continues servicing the dial, display and controller, and that Wi-Fi reconnects and acquires an address. Measure the maximum service interval under concurrent local HTTP requests, stock recipe sync and Wi-Fi loss. The wired simulation's 4 ms foreground regression budget is a comparison point.
