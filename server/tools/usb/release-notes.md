The Hub and custom firmware for Pico S, Pico Pro, both Pico C display variants, individual Z-series modules, Zymatic, PicoFerm and PicoStill are **1.0.0**. Update the Hub to get new browser and journal features without reflashing a machine that already runs the matching firmware.

Use the Hub to build recipes, control compatible machines, review brew history, and see model-specific cleaning reminders. A paired PicoFerm records while its Wi-Fi radio sleeps. A short press wakes it for management. To connect a standalone PicoFerm to a batch, open the batch in **Brew journal**, choose **Ferment**, and select its monitor. To convert a stock machine, connect it to the computer running the Hub and open **Brewery → Add machine → USB setup and recovery**. Keep a private copy of the Hub data directory after it saves the original firmware.

With factory firmware, Pico S, Pro and C can fetch recipes from the Hub and report brew sessions. A stock Z module running 0.0.119 can report live readings and accept a recipe directly from the Hub. Open **Brewery → Add machine → Add a stock brewer** to register one. For grouped stock Z modules, offer the staged recipe from the Hub, confirm each recipient and start at its dial. [Stock brewer setup](https://github.com/jeffreydwalter/picobrew/blob/v1.0.0/server/docs/stock-brewers.md)

On the Brewery page, select **Group machines** to link individual brewers for a larger batch or a side-by-side comparison. Each invited brewer accepts separately. A compatible Z can use its dial, local website or the Hub. Grouped Z modules can also share coffee settings and invite each other to sous vide, PicoStill and utility programs. A standalone Z supports Wi-Fi and wired Ethernet and can pair with either a standalone PicoStill or a stock PicoStill on firmware 0.0.35. Its recipe library supports up to 20 steps in a Z Program Maker program, archived Z recipes with their setup water, and original PicoPak schedules for use with the physical adapter. [Z features and compatibility](https://github.com/jeffreydwalter/picobrew/blob/v1.0.0/firmware/z-series/modified/oem-parity.md)

This build fixes Group Brewing invitations on standalone Z modules that are asleep or about to enter standby. The Hub now shows the brewer’s dial decision even if it polls after the invitation deadline, and reports when a safety interlock prevents an accepted brew from starting. Update the Hub for the reporting fixes and the Z firmware for the standby fixes.

The brew assistant supports Google Gemini with a Google AI Studio API key. Open **Settings → AI** to choose the provider and a model available to your key. You can draft a recipe, ask about a live brew, or review a recorded session.

If your brewer runs development firmware with a higher version number, update the Hub first. Select **Check for Updates** on the machine’s Firmware page. Wireless installation requires the matching recovery layout. For an earlier dual-bank PicoFerm running 1.0.0, connect it by USB and choose **Install standalone firmware** in the Hub that holds its original backup and device key. The installer verifies the existing banks and preserves the device’s history and pairing. Earlier layouts without recovery and both Zymatic profiles also use USB. A Zymatic on stock 1.1.14 can fetch recipes and report sessions to the Hub over Wi-Fi. Open its brew journal to see all four temperature readings, step changes, and reported errors, or export them as CSV or JSON. Its local website and API work over Wi-Fi at Home and for readings at programmed pauses. Use Ethernet for continuous access during heating, circulation and draining. Zymatic firmware is prepared with the individual brewer’s identity. Physical qualification varies by model. [Setup and compatibility](https://github.com/jeffreydwalter/picobrew#3-connect-your-machine)

Download the **picobrew-hub** executable for your computer. Run it with `--version` to check the release. It includes the Hub website, USB programmer and firmware resources. The separate `picobrew-usb` executables are build inputs for users building the Hub from source. `SHA256SUMS.txt` covers all downloads. `releases.json` identifies the exact source commit and the size and SHA-256 of every Hub and worker.

Use Linux ARM64 for a 64-bit Raspberry Pi OS installation and Linux ARM for 32-bit Raspberry Pi OS on ARMv7 or newer. Linux binaries use glibc. USB access requires the Hub account to have access to the physical port or USB adapter. Follow the device and power prompts in the Hub. Backup and setup preserve the existing model and flash-layout checks. Firmware changes for a named Z stack require independently qualifying its individual module.

The [firmware catalog for this release](https://github.com/jeffreydwalter/picobrew/blob/v1.0.0/firmware/releases.json) lists the Pico S, Pro, C, Z, PicoStill, and PicoFerm packages and their checksums. The USB installer prepares the Zymatic image for each brewer. The USB worker includes the project’s MCU-specific tools, the CPython runtime and third-party libraries. The accompanying source archive contains the programmer sources. Each platform has a ZIP with the license for original project contributions, the Hub license and the runtime and dependency notices from its build. OEM images, artwork, recipes and manuals retain their existing notices.
